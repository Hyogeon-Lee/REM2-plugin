# 선행 연구 DB 가이드

이 vault에 논문을 넣고 관리하는 규칙이다. 노트, 그림 후보, 커버, Base, 캔버스 카드는 모두 `build_db.py`가 `00_candidates.json`을 읽어 만든다. 사람이 하는 일은 네 가지다: JSON에 항목 추가, PDF 저장, 스크립트 실행, 대표 그림 확인.

## 이 DB의 결정 사항

처음 만들 때 정한 내용이다. 논문을 추가하는 사람과 Claude는 이 표대로 진행한다. 결정을 바꾸면 이 표도 고친다.

| 항목 | 결정 |
|---|---|
| 용도와 읽는 사람 | |
| 묶는 기준 | 연구 주장 트랙 |
| 카드 그림 | 장치 사진, 없으면 시스템 구성도 |
| 연결 관계 | 직접 관계만, 라벨 없음 |
| PDF 확보 | 사용자가 직접 넣음 |

## 폴더 구조

이 폴더 자체가 Obsidian vault다. Obsidian에서 "폴더를 보관함으로 열기"(Open folder as vault)로 이 폴더를 연다. 모든 경로가 이 폴더 기준이므로 폴더를 통째로 복사하거나 이름을 바꿔도 링크, Base, 캔버스가 그대로 작동한다.

Windows 경로 한도는 259자다. 스크립트 실행 결과의 `Windows path budget` 줄이 vault 폴더 전체 경로의 최대 길이를 알려 준다. vault를 그보다 긴 경로에 두면 이름이 긴 파일이 복사되지 않거나 열리지 않을 수 있다.

| 위치 | 내용 | 쓰는 쪽 |
|---|---|---|
| `00_candidates.json` | 트랙 정의와 논문 목록 (원본 데이터) | 사람 |
| `pdf/` | 논문 PDF | 사람 (vault 최상위 폴더에 두면 스크립트가 `pdf/`로 옮김) |
| `detail/DB_<PDF 이름>.md` | 논문별 노트 | 스크립트 + 사람 (`hw`, 메모) |
| `img/` | 그림 후보 `DB_<PDF 이름>_cN`, 커버 `DB_<PDF 이름>_cover.jpg` | 스크립트 + 사람 (수동 크롭) |
| `00_Database.base` | 카드 갤러리, 트랙별 뷰, 전체 목록 표 | 스크립트가 처음 한 번 만들고, 그 뒤로는 사람 |
| `00_Map.canvas` | 트랙별 지도 | 스크립트가 새 카드와 연결선만 추가 |
| `build_db.py` | 생성 스크립트 | |
| `.obsidian/` | Obsidian 설정 (Bases, Canvas 코어 플러그인 켜짐) | Obsidian |

## 추가 절차

1. **중복 확인**: `00_candidates.json`에서 DOI와 제목으로 검색한다. 같은 논문의 프리프린트와 출판본이 있으면 출판본만 남긴다.
2. **항목 추가**: `papers` 배열 끝에 [[#항목 템플릿]]을 붙이고 채운다. `id`는 마지막 번호에 1을 더한다 (마지막이 P012이면 P013).
3. **PDF 저장**: `filename` 값과 정확히 같은 이름으로 vault 최상위 폴더 또는 `pdf/`에 저장한다. PDF를 구할 수 없으면 이 단계를 건너뛰고 `status`에 `접근 불가`, `status_note`에 이유를 적는다.
4. **스크립트 실행**: [[#실행]] 참고.
5. **대표 그림 확인**: 새 노트의 "그림 후보" 접힌 칸을 열고, 논문을 가장 잘 떠올리게 하는 그림(장치 사진, 시스템 구성도) 번호 1~2개를 `hw` 속성에 적는다. 처음에는 점수가 높은 후보 두 개가 자동으로 들어가는데, 그래프나 실험 장면이 섞일 수 있다.
6. 후보 중에 쓸 그림이 없으면 [[#수동 크롭]]을 한다.
7. `hw`를 바꿨으면 스크립트를 다시 실행한다.
8. `00_Database.base`와 `00_Map.canvas`에서 카드를 확인한다.

## 항목 템플릿

앞 항목의 `}` 뒤에 쉼표를 붙인 다음 이 블록을 넣는다.

```json
{
  "id": "P013",
  "title": "논문 원제목",
  "authors": "Last1, Last2, Last3",
  "year": 2026,
  "venue_abbrev": "ICRA",
  "doi": "10.1109/...",
  "landing_url": "https://doi.org/10.1109/...",
  "tracks": ["A", "C"],
  "tier": 2,
  "reason": "이 논문이 어떤 트랙 주장을 뒷받침하는지 한두 문장",
  "key_numbers": "응답 속도, 지연, 정확도 같은 수치",
  "numbers_source": "abstract",
  "related": ["P004"],
  "filename": "2026_ICRA_논문 원제목.pdf",
  "status": "대기",
  "status_note": ""
}
```

## 필드 규칙

필수 키가 없거나, `tracks`에 정의되지 않은 트랙을 쓰거나, `related`에 없는 `id`를 쓰면 스크립트가 노트, 그림, Base, 캔버스를 쓰기 전에 멈추고 오류 목록을 보여 준다.

| 키 | 필수 | 규칙 |
|---|---|---|
| `id` | ○ | `P` + 세 자리 번호. 한 번 정하면 바꾸지 않는다. |
| `title` | ○ | 원문 제목 그대로 |
| `year` | ○ | 따옴표 없는 숫자 |
| `venue_abbrev` | ○ | 약어: `ICRA`, `IROS`, `IEEE Robot. Autom. Lett.`, `arXiv` |
| `tracks` | ○ | 트랙 문자 배열: `["A", "C"]`. [[#트랙]] 참고 |
| `filename` | ○ | [[#파일명 규칙]] 참고 |
| `status` | ○ | `대기` 또는 `접근 불가`. PDF가 있으면 노트에는 스크립트가 `다운로드 완료`로 쓴다. |
| `authors` | | 성만 쉼표로 구분: `Chen, Khamis, Lepora` |
| `doi`, `landing_url` | | DOI(`10.xxxx/...`)와 논문 페이지 URL. 노트의 DOI 링크가 된다. |
| `tier` | | [[#우선순위]] 참고 |
| `reason`, `key_numbers`, `numbers_source` | | 넣은 이유, 핵심 수치, 수치 출처(`abstract`, `full text`, `secondary source`, `none seen`). 노트의 접힌 칸에 나온다. |
| `related` | | 관련 논문 `id` 배열. [[#연결 관계]] 참고 |
| 그 밖의 키 | | 스크립트는 읽지 않는다. 기록용으로 자유롭게 둔다. |

## 파일명 규칙

`연도_게재지약어_제목.pdf`

- 게재지 약어에서는 영문자와 숫자만 남긴다: `IEEE Robot. Autom. Lett.` → `IEEERobotAutomLett`
- 제목에서 `\ / : * ? " < > | # ^ [ ]`는 지우고 (`# ^ [ ]`가 들어간 이름은 위키링크가 작동하지 않는다), `—`와 `–`는 `-`로 바꾼다.
- 제목이 길어 파일명이 150자를 넘으면 제목 끝을 자른다.
- 예: `2023_ICRA_Design of a Multimodal Fingertip Sensor for Dynamic Manipulation.pdf`

JSON의 `filename`과 실제 PDF 이름이 한 글자라도 다르면 스크립트는 PDF가 없다고 판단한다.

노트와 그림 이름도 이 값으로 만든다. `DB_` + `filename`에서 `.pdf`를 뺀 이름이 기본 이름이다.

- 노트: `기본 이름.md`
- 그림 후보: `기본 이름_cN.jpg`
- 커버: `기본 이름_cover.jpg`

## 트랙

트랙은 이 DB가 뒷받침하려는 연구 주장 하나하나다. `00_candidates.json`의 `tracks`에 정의한다.

```json
"tracks": {
  "C": "[Novelty] 제안 방법이 새로 보여 주는 것",
  "B": "[한계] 기존 방법의 한계",
  "A": "[선행 연구] 기존 방법"
}
```

- 한 논문에 트랙을 여러 개 붙일 수 있다. Base의 트랙별 뷰는 `tracks`에 그 문자가 있으면 보여 준다. AC 논문은 A, C 뷰에 모두 나온다.
- 캔버스 그룹은 논문의 트랙 중 `tracks` 정의에서 **가장 위에 적힌 것** 하나로 정한다. 위 예시에서 AC 논문은 C 그룹에 들어간다. 그래서 새로움(Novelty)에 가까운 트랙을 위에 적는다.
- 다른 그룹에 두고 싶으면 캔버스에서 카드를 직접 옮긴다. 스크립트는 이미 있는 카드를 옮기지 않는다.
- 트랙을 추가하면 다음 실행 때 캔버스 그룹이 새로 생긴다. Base 뷰는 자동으로 늘지 않으므로 `00_Database.base`에 뷰를 직접 추가하거나, 뷰를 고친 적이 없다면 `00_Database.base`를 지우고 다시 실행한다.
- 트랙 이름(오른쪽 글)을 바꾸면 캔버스에서 그 그룹의 라벨도 `<문자> · <새 글>`로 똑같이 바꾼다. 바꾸지 않으면 그 트랙에 새 논문이 들어올 때 맨 아래에 그룹이 하나 더 생긴다. Base의 트랙 뷰 이름은 `00_Database.base`에서 직접 고친다.

## 연결 관계

- `related`에 적은 논문과는 캔버스에 연결선이 생기고, 노트 속성 `related`에 링크가 들어간다. 그래프 뷰와 백링크에도 나온다.
- 한쪽에만 적으면 된다. 같은 쌍에 연결선을 두 번 만들지 않는다.
- 연결선은 두 논문 모두 커버가 있어 캔버스에 올라가 있을 때만 생긴다.
- 연결선의 의미(같은 연구실, 후속 연구, 같은 방법 등)는 캔버스에서 연결선을 선택해 라벨로 적는다. 스크립트는 이미 있는 연결선을 고치지 않으므로 라벨은 남는다.

## 우선순위

| `tier` | 뜻 |
|---|---|
| 1 | 전문 필독 |
| 2 | 읽기 권장 |
| 3 | 선택 |

## 상태와 표시 위치

- PDF가 `pdf/`에 있으면 노트의 `status`는 `다운로드 완료`가 된다. JSON의 `status`는 고치지 않아도 된다.
- PDF가 없으면 JSON의 `status`가 노트에 그대로 들어간다.
- 그림 갤러리와 트랙 뷰는 `다운로드 완료`인 논문만 보여 준다. PDF가 없는 논문은 "전체 목록" 표에만 나온다.
- 캔버스에는 커버 이미지가 있는 논문만 올라간다.

## 대표 그림

- 첫 실행 때 스크립트가 PDF에서 사진형 그림을 최대 6장 잘라 `img/DB_<PDF 이름>_c1.jpg` ~ `_c6.jpg`로 저장한다. 벡터로 그린 그래프는 뽑지 않는다.
- 자동 추출은 그 논문의 후보 이미지가 하나도 없을 때만 실행된다. 수동 크롭을 첫 실행 전에 넣으면 자동 추출이 건너뛰어지므로, 크롭은 첫 실행 뒤에 넣는다.
- `hw`는 커버에 쓸 후보 번호이고, 적은 순서대로 왼쪽부터 붙는다. 노트 속성에서 `hw: [3, 1]`처럼 적는다.
- 커버는 각 그림의 높이를 맞춰 가로로 붙인 이미지다. 카드 이미지 영역은 가로:세로 = 2:1이므로, 가로로 긴 그림 1장이나 정사각형에 가까운 그림 2장이 잘 맞는다.
- `hw: []`로 비우면 커버를 만들지 않는다. 그 논문은 실행 결과의 "수동 크롭 필요" 목록에 나온다.

### 수동 크롭

1. PDF를 200% 이상 확대한 다음, 쓸 그림을 캡처해 `img/DB_<PDF 이름>_c7.png`로 저장한다. 노트 이름에서 `.md`를 `_c7.png`로 바꾼 이름이다. Win+Shift+S로 캡처해도 된다. 자동 후보 1~6과 겹치지 않도록 번호는 7부터 쓴다. 확장자는 jpg와 png 모두 된다.
2. 노트의 `hw`에 그 번호를 넣는다: `hw: [7]`
3. 스크립트를 다시 실행한다.

스캔본 PDF(페이지 전체가 한 장의 이미지)는 자동 추출이 되지 않으므로 항상 수동 크롭을 한다.

## 노트 편집

| 부분 | 스크립트를 다시 실행하면 |
|---|---|
| 속성 `title`, `aliases`, `authors`, `year`, `venue`, `tracks`, `tier`, `status`, `doi`, `url`, `pdf`, `cover`, `related` | JSON 값으로 덮어쓴다. 고치려면 JSON에서 고친다. |
| 그 밖의 속성 (`hw`, 직접 만든 속성) | 그대로 둔다. |
| `<!-- auto:start -->`부터 `<!-- auto:end -->`까지 | 매번 새로 쓴다. 이 사이에는 아무것도 적지 않는다. |
| `<!-- auto:end -->` 아래 (`## 메모` 등) | 그대로 둔다. |

## 캔버스

- 실행할 때 캔버스에 없는 논문만 추가한다. 이미 있는 카드의 위치는 바꾸지 않는다.
- 새 카드는 해당 트랙 그룹의 첫 빈칸에 들어간다. 그룹은 5열 격자이고 카드 크기는 440 × 400이다. 그룹이 가득 차면 한 행 늘어나고, 그 그룹 아래에 있는 그룹과 카드도 같은 만큼 내려간다. 옆에 나란히 둔 그룹은 움직이지 않는다. 폭이 일부만 겹치게 엇갈려 둔 그룹은 늘어날 때 서로 겹칠 수 있으니, 그룹은 세로로 쌓거나 옆으로 완전히 떨어뜨려 둔다.
- 그룹 라벨은 `<문자> · <트랙 글>`과 같게 둔다. 스크립트는 새 카드를 넣을 때 라벨 글자로 그룹을 찾으므로, 라벨이 다르면 그 트랙에 새 논문이 들어올 때 캔버스 맨 아래에 그룹이 하나 더 생긴다.
- 캔버스에서 지운 카드나 `related` 연결선은 다음 실행 때 다시 생긴다. 논문을 아예 빼려면 [[#논문 삭제]]를 따르고, 연결선을 빼려면 JSON의 `related`에서 지운다.

## 하지 말 것

- `id`를 바꾸거나 이미 쓴 번호를 다시 쓰지 않는다.
- PDF 이름만 바꾸지 않는다. 바꿀 때는 JSON의 `filename`, PDF, 노트(`DB_...md`), 그림(`img/DB_..._*`) 이름을 같은 규칙으로 함께 바꾸고, 캔버스에 깨진 카드가 생기면 지운다.
- 노트 이름만 바꾸지 않는다. 노트 이름이 규칙과 다르면 다음 실행 때 같은 논문의 노트가 하나 더 생기고, `hw`와 메모는 예전 노트에만 남는다.

## 논문 삭제

스크립트는 파일을 지우지 않는다. 아래를 모두 직접 지운다.

1. `00_candidates.json`의 항목 (다른 항목의 `related`에 이 `id`가 있으면 그것도)
2. `detail/DB_<PDF 이름>.md`
3. `img/DB_<PDF 이름>_*`
4. `pdf/`의 PDF
5. `00_Map.canvas`의 카드

## 실행

vault 최상위 폴더(이 문서가 있는 폴더)에서 실행한다.

```powershell
python build_db.py
```

- 필요한 패키지: `pip install pymupdf pyyaml` (Python 3.9 이상)
- 출력 `notes 40, covers 31, canvas +2 cards +1 edges`는 차례로 노트 수, 커버가 있는 논문 수, 이번에 캔버스에 추가된 카드 수와 연결선 수다.
- 출력 끝의 "PDF 있으나 대표 그림 없음" 목록은 수동 크롭이 필요한 논문이다.
- 여러 번 실행해도 결과는 같다.

## 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| `missing key`, `not in "tracks"`, `related id ... not found` | JSON 항목 오류 | 오류 목록의 `id` 항목을 [[#필드 규칙]]과 비교 |
| `json.decoder.JSONDecodeError` | 쉼표나 따옴표 오류 | 오류 메시지의 줄 번호 위치 확인 |
